# T Design System — гайд по применению для агента

Этот документ описывает, **как агенту собирать интерфейсы из этой дизайн-системы**: какие токены использовать, какие компоненты существуют, их пропсы и правила применения. В репозитории источник правды — код в `src/`; в установленном пакете сверяйся с доступными декларациями `.d.ts` и CSS. Если этот гайд расходится с кодом или API установленной версии, прав код.

---

## 1. Базовые правила

1. **Один раз подключи стили** в корне приложения — без них компоненты выглядят сломанно:
   ```tsx
   import '@pluginwoman/t-ds/style.css'
   ```
   > До версии 1.5.3 использовался путь `@pluginwoman/t-ds/style` (без `.css`) — он продолжает работать для обратной совместимости, но не резолвится бандлерными ambient-типами `*.css` (TS-ошибка `TS2882` без ручного `declare module` в проекте). Для новых проектов используй `.../style.css`.
2. **Импортируй компоненты из корня пакета, иконки — из subpath `/icons`:**
   ```tsx
   import { Button, Cell, Input } from '@pluginwoman/t-ds'
   import { Circle, ChevronRight } from '@pluginwoman/t-ds/icons'
   ```
   > Иконки экспортируются без суффикса `Icon` (`Circle`, `ChevronRight`, …). Общий barrel содержит преимущественно 24px Stroked; для другого размера или начертания используй соответствующий subpath.
3. **Никогда не хардкодь и не создавай новые цвета, текстовые стили, переменные размеров, отступы, скругления, тени.** Только CSS-переменные из дизайн-системы и готовые типографические классы `ts-*`. Нельзя: новые CSS-классы с `font-size`/`font-weight`, новые CSS-переменные `--my-*-color` / `--my-*-size`, хардкод hex-значений или числовых размеров. Подробные правила и доступные значения — в [гайде по токенам](./AGENTS.tokens.md).
4. **Прежде чем верстать элемент вручную, проверь — нет ли подходящего компонента в t-ds.** Сравнивай по названию: как называется слой/компонент в Фигме — ищи компонент с тем же именем в каталоге (раздел 4). Почти все паттерны (кнопки, поля, ячейки, модалки, шиты, навигация) уже есть. **Не пиши свои аналоги существующих компонентов.** Каталог и правила применения — в [гайде по компонентам](./AGENTS.components.md).
5. **Обычно булевы пропсы именуются `is*` / `has*`** (`isDisabled`, `isLoading`, `hasDescription`), а колбэки — `on*` (`onClick`, `onChange`, `onClose`). Используй фактические имена из API конкретного компонента.
6. **Многие контейнерные компоненты составные** (`Modal` + `ModalHeader` + `ModalFooter`, `Drawer`, `ActionSheet`, `Footer`, `Widget`, `Table`). Собирай их из частей, а не одним пропсом.
7. **Строковые enum-пропсы регистрозависимы.** `size`, `variant`, `layout` и т.п. — строго в нижнем регистре (`size="m"`, не `"M"`). Неверный регистр молча ломает раскладку: класс `page-layout--M` просто не существует, и компонент остаётся без размерных стилей. Допустимые значения смотри в типе пропа.

### Установка и базовый CSS-reset

Шрифт **TT Norms Tochka Extended** на macOS по умолчанию рендерится субпиксельно и выглядит «жирным». Добавь сглаживание в корневой reset, иначе типографика библиотеки отображается некорректно:

```css
html { -webkit-font-smoothing: antialiased; -moz-osx-font-smoothing: grayscale; }
```

### Хуки и утилиты

- **`useScrollTo`** — возвращает обработчик для плавной прокрутки к цели по клику. Принимает DOM-элемент, React ref или CSS-селектор и необязательные `ScrollIntoViewOptions`. По умолчанию использует `behavior: "smooth"` и `block: "center"`, как в промо-лендингах.
  ```tsx
  const targetRef = useRef<HTMLElement>(null);
  const scrollToTarget = useScrollTo(targetRef);

  <Button onClick={scrollToTarget}>Перейти к секции</Button>
  <section ref={targetRef}>...</section>
  ```
- **`scrollToElement`** — императивная версия `useScrollTo` для вызова внутри обычного обработчика или функции. Принимает те же цели и параметры.
- **`useIsMobile`** — возвращает `boolean` для переключения размеров шрифта и других адаптивных вариантов по breakpoint. По умолчанию используется `BREAKPOINT_MOBILE`, при необходимости передай breakpoint вручную. Хук работает только на клиенте: в SSR-проектах его нельзя использовать в серверных компонентах без client boundary. Во время SSR `window` недоступен, поэтому начальное значение не отражает реальную ширину viewport до гидрации.
  ```tsx
  const isMobile = useIsMobile(BREAKPOINT_TABLET);

  <PromoPageTitle className={isMobile ? 'ts-600-3xl' : 'ts-600-5xl'}>
    Заголовок
  </PromoPageTitle>
  ```

## 5. Примеры компоновки компонентов

Подробные сценарии сборки типовых интерфейсов и паттернов находятся в скилле `$dt-ui-builder`. Выбирай материалы по текущей задаче. Правила применения смотри в гайдах `AGENTS.md` и связанных файлах, поставляемых вместе с библиотекой (в vendored-проекте — `vendor/@pluginwoman/t-ds/AGENTS.md`); API — в `.d.ts` установленной версии. Если инструкция и декларации расходятся, не используй props, отсутствующие в `.d.ts`.

## 6. Чеклист перед сдачей UI
- [ ] Стили подключены (`import '@pluginwoman/t-ds/style.css'`); в reset добавлен `-webkit-font-smoothing: antialiased`.
- [ ] Нет хардкода цвета/шрифта/отступа/радиуса/тени — только токены и `ts-*`-классы (в Tailwind — `text-[var(--…)]`).
- [ ] `size`/`variant`/`layout` заданы в нижнем регистре.
- [ ] При фиксированном хедере над `PageLayout` задан `topOffset`; `Footer` — последний сиблинг потока.
- [ ] Использованы готовые компоненты вместо самописных аналогов.
- [ ] Аксессуары ячеек — через `CellLeftAccessory`/`CellRightAccessory`.
- [ ] Оверлеи управляются `isOpen` и корректно закрываются по `onClose`.
- [ ] Интерактивные элементы имеют `onClick`/`onChange`; иконочные кнопки реализованы через `IconButton` с обязательным `ariaLabel`.
- [ ] Иконки обёрнуты в `.ds-icon ds-icon--{size}` (или переданы пропсом, где компонент оборачивает сам); правила — в [гайде по иконкам](./AGENTS.icons.md).
- [ ] В `Dropdown` у `Cell`-элементов списка отключены ненужные `hasLeftAccessory`/`hasRightAccessory`; `value` — человекочитаемая строка; выбранный элемент выделен галочкой. Подробный сценарий — в скилле `$dt-ui-builder`.
- [ ] Компоненты внутри `Modal`/`Drawer` не добавляют собственных горизонтальных паддингов; если компонент управляет отступами сам — обнулён `.modal__content-inner` / `.drawer__content-inner` через CSS.
